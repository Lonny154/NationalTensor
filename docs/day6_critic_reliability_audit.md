# Day 6 — Experiment 009 critic reliability audit

**Scope:** Five preserved Experiment 008 criticism requests made for Experiment 009 proposals P02–P06. This is an offline audit of the original responses and their validated source packages. It does not promote any rejected response to accepted criticism or change the Experiment 009 protocol.

## Executive summary

All five requests are genuinely rejected in their manifested local audits. Four responses use numerical summaries that are not literal values in their cited observations; P05 mentions Experiments 003 and 004 without citing either evidence ID. The first deterministic error in each case is reproducible from the current validator. The errors are useful gates, but they do not exhaust the scientific issues in the responses. In particular, citations are global across criticism fields, so a valid reference can coexist with an unsupported interpretation or an uncited claim in a different field.

The highest-priority improvement is a **claim-level evidence plan for the critic prompt**: require each historical or measured numerical assertion to identify its exact observation key, and require rounded or derived values to show operands and arithmetic or use the recorded value verbatim. This would make review easier without weakening rejection criteria. Any new prompt or parser behavior must be versioned separately from the frozen Experiment 009 comparison; the present P02–P06 failures must remain recorded failures.

## Evidence and validation boundary

The cases are under `evaluations/muse-research-critic/v1/<case-id>/`, with `setup/case.json`, `criticism/audit.json`, and manifests. These directories are local and ignored by Git. The source packages contain the original proposal, validated observations, evidence IDs, and the critic prompt. The audit stores the original raw response and its first validation error. All five have `parsed_response: null`, `status: rejected`, and `rejection_kind: invalid_response`; no revision was requested. The documented read-only `--validate` path confirms the stored outcomes. This audit reads the rejected JSON for diagnosis; its prose is **not accepted scientific assessment**.

## Failure taxonomy and root causes

1. **Unsupported numerical claims or incorrect citation coverage:** P02 and P04 assert a median “near 1.0” while citing E005 status/scope keys rather than screening records. P03 describes four shapes while citing only one shape's two screening records. These are model citation failures, even when the underlying source contains related measurements.
2. **Rounded and derived numbers outside the literal-value grammar:** P03 and P06 turn recorded ratios into decimal ranges. The validator compares numeric strings rather than checking a declared rounding calculation. P06 has all four relevant timing keys, so its first error demonstrates overly restrictive text matching for an approximate summary. No incorrect explicit arithmetic was found as the *recorded first cause* of a P02–P06 rejection. P05's 4.5 MiB full-matrix calculation is a separate inference requiring review, not the recorded error.
3. **Missing or incorrectly scoped historical citations:** P05 omits E003 entirely. E004 is present but only its `control_workload` key is cited for a compiler-equivalence assertion. The parser detects the missing E003 **ID** but not the E004 observation-key mismatch. P04 likewise cites E003/E004 IDs for assertions beyond the cited keys. This is a demonstrated validator false negative for claim-to-key support, not a reason to relax the P05 rejection.
4. **Screening versus confirmation:** All E005 comparisons are screening. Several responses say the intervals include 1 and confirmation is missing; that framing is directionally appropriate. None may claim a confirmed speedup or locality mechanism. P03 and P06 extrapolate Hilbert screening to the prospect of a *different* grouped candidate; that is advisory inference, not an observation about the proposed kernel. E005's `verification.limitations` explicitly say program-ID order need not equal physical CTA order and compiler differences alone do not establish locality benefit.
5. **Observation versus inference:** P02's “no edge tiles” follows from dimensions and tile sizes but remains a calculation, not a measurement of its proposed variant. P04's imbalance mechanism and P05's slab-residency conclusion are unmeasured. P05's assertion that a full matrix cannot reside on one SM does not establish that the proposed slab cannot. The validator cannot adjudicate these mechanism claims.
6. **Evidence presentation:** The source already includes exact ratios and units (`median_paired_ratio` is unitless; latency fields are milliseconds), but packs eight nested timing records among many observations and supplies one global citation list. No case shows evidence **absent from the prompt**: E005's records are present in each source package. The demonstrated issue is selection and scoping of available keys, plus pressure to compress long numbers into readable prose. An evidence table may help, but its benefit is a hypothesis for a future study.

The validator's broad number allowance is another limitation: `_check_text` unions all numbers from the original proposal and cited values. It permits a number found somewhere in that union even when the sentence attributes it to a different observation, and it permits configuration/workload numbers from any cited experiment ID in criticism mode. Regexes for “confirmed,” “speedup,” and performance units catch some dangerous phrasings but cannot establish scientific meaning and may miss paraphrases. These are code-level limitations; this audit did not measure their prevalence in accepted responses.

## Recommended interventions

| Rank | Intervention | Expected scientific value | Effort | Validation risk |
| --- | --- | --- | --- | --- |
| **1** | Version a critic instruction/schema that asks for a compact claim ledger: exact evidence ID and observation key for each historical and quantitative claim, recorded value with units or explicitly marked inference, and no rounded ratio unless operands and rounding precision are supplied. Keep it concise enough for the response limit. | High: directly addresses the demonstrated citation and number failures and makes human review faster. | Low–medium | Low for scientific standards; **high protocol risk if applied inside the frozen Experiment 009 run**, so use a new versioned attempt/study. |
| **2** | Present E005 screening as a structured table with shape, opponent, exact unitless median ratio, interval, screening label, and corresponding observation key; surface E003/E004 result keys alongside workload keys. | Medium: makes the right key easier to select and separates measurement from limitations. Benefit remains unmeasured. | Low–medium | Low if source facts are generated from validated observations; version the prompt/source package for new Muse comparisons. |
| **3** | Add narrowly scoped validator support for explicit decimal rounding and range summaries **only** when every referenced screening record is cited and each endpoint is reproducible from those values at a declared precision. Preserve exact-value and stage checks. | Medium: resolves P06-style brittle matching while retaining evidence discipline. | Medium | Medium: a broad tolerance or generic “near” exception could admit false claims. Do not add one. |
| **4** | Diagnose citation-to-claim support with field-scoped references or a claim ledger checked against required observation keys for known recorded facts. | Medium: addresses P04/P05 key mismatches and global-citation false negatives. | Medium–high | Medium: prose matching can create false confidence; limit automation to references, recorded values, and explicit arithmetic. Human review still judges interpretation. |

Do not tune the acceptance rate as a target. An accepted JSON response remains only structurally and numerically validated; human review decides whether criticism is scientifically useful.

## CPU-only regression-test plan

- Add read-only fixture loaders for the five manifested local audits, asserting case/proposal identity, original rejection status, first error category and field, and manifest integrity. Use copied minimal JSON fixtures for a source-only CI path because `evaluations/` is ignored by Git; exclude raw prompts, raw responses, and local environment identifiers from committed fixtures.
- For P02/P04, supply synthetic text with E005 status/scope citations and “near 1.0”; assert rejection. Add a screening citation plus an exact recorded ratio in a synthetic response and assert the numerical gate accepts that *field*, while human review still evaluates the interpretation.
- For P03, test that a four-shape interval summary cannot be supported by only the two 128-shape timing keys. Test exact recorded values and an explicitly computed, correctly scoped rounded range separately.
- For P05, test bare `003` without E003 ID, then E003 ID with a mismatched key. The former must reject deterministically; the latter is a known gap to close through structured claim references rather than general prose inference. Also test that full-matrix arithmetic is not treated as evidence against an unspecified slab.
- For P06, test the four exact cited ratios and intervals; a future rounding rule should accept `0.997–1.002` **only** with those four keys and declared three-decimal rounding, and reject altered endpoints, omitted keys, or a claimed confirmed speedup.
- Add explicit arithmetic fixtures for correct and incorrect operand calculations, plus screening/confirmation wording fixtures. Keep all cases CPU-only and avoid Muse or GPU calls. Tests should assert scientific boundary labels, not merely that a response parses.

## Experiment 009 implications

The existing six-proposal A/B comparison has only P01 bound to accepted criticism and P01-A/P01-B decisions. Its source hashes, frozen decision prompt, rubric, and condition isolation remain intact if this audit is only documentation and offline tests are added. Improving a future critic prompt or evidence layout changes the criticism given to B, and changing deterministic acceptance rules changes which criticisms qualify for binding. Either affects the treatment for P02–P06 and requires a separately versioned protocol or new run, with historical outcomes preserved. An explicit offline revalidation is available in Experiment 008, but reclassifying old responses for this pilot would need a predeclared rule and human scientific review; it must not silently substitute for independent new criticism. The existing pilot cannot yet estimate decision-quality improvement or GPU compute savings.
